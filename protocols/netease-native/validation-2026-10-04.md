## Windows 原生字段

relay 源列表和状态提交分别为 `songListSubmitReq`、`playStateSubmitReq` 的 JSON 字符串。模式是 `order / random / single_loop / list_loop`；歌曲 progress 为 0，未观察到歌曲周期进度上传。官方强制补传仅在明确 10001 时生成新会话并按配置 snapshotSize 截取当前歌曲附近的快照，不继续循环提交状态。普通超时、断线和结果未知不补传。

原生 ADD 继续使用 roomId 和序列化 playlistParam，增量携带歌曲 ID、仅增加本机版本，不改已有播放模式或替换整个队列。服务端 version.userId 原有数字或字符串类型原样保留，账号比较仅在本机转成字符串；不存在本机版本时，按已观察的 Windows 逻辑加入数字 UID。新增歌曲先验证官方详情，随后读取房间列表确认，未知详情不产生写入；没有新增 endpoint 或未知模式值。

## 后续抓包所需内容

在线上报需要能关联开启/关闭可见性、登录、前后台、正常退出、断网重连的认证与续期事件、服务器确认及离线时限。只有隐私字段、wss 地址或手机上的“在线”文字不够。安卓总结卡需要一条成功生成的脱敏类型和受控 payload；私有 WS 需要认证、帧格式、序列、ACK、补历史和重连续传。未核验前保持未实现状态，不能向现有 endpoint 发送猜测字段。

双人口味心动推荐仍需开启/关闭请求、listMode/参数回显、队列是否替换和权限失败响应；不以个人心动模式、每日推荐或空模式值替代。

## 接管与新观测边界

已有房间接管在首次原生心跳成功后重新读取并核对房间，才记录归属与恢复状态；参数来自服务器当前歌曲、进度和播放状态，不使用接管前的普通播放器进度。新增六项测试不改变端点及加密层。

本轮私有只读观测仍返回普通模式。18 条 type 23 通用消息的 `generalMsg.webUrl` 仅为应用升级页，未含一起听总结的时长等结构，不能据此伪造总结卡。Windows 客户端二进制中发现 `/api/listen/together/yunxin/token/get` 和 `/api/middle/im/token/get` 字符串；请求参数、IM 认证和 ACK 尚未核验，未加入生产接口。token 名称也不能证明它是账号在线状态上报协议。原始载荷、账号和 Cookie 仅保存在工作区私有 work 目录，不进入仓库。

## 本账号新建房间的本地进度种子

房间创建响应的 creatorId 与成员需对应当前账号，后续读到的 roomId 必须仍一致，才允许初始化。首个 GOTO 使用已有 commandInfo 字段，带当前网易云歌曲、引擎毫秒进度和播放状态；上报前限制进度范围。推荐歌曲从零播放。接管、接受邀请和恢复已有房间使用房间歌曲/进度，不能复用种子；引擎未加载时的后续指令也不能将旧曲零位置覆盖房间。新增测试验证单次指令与来源隔离；真实网络确认与体验仍由用户验收。

## 自动接续的证据边界

自动接续仅重用已验证的增量 ADD、NEXT、GOTO 和只读推荐，不增加协议端点、字段或加密方式。SPlayer 自行选择普通列表末尾的推荐候选；四秒房主无响应后的房员接续也属于本客户端策略，不能称为官方在线判定或服务器房主迁移。最新普通房间成员字段仍未包含可靠的在线/设备状态。单曲循环、heart 和未知模式不混入个人推荐。自动检查覆盖未知写入不重放、取消、队列保留和重复事件，真实自然结束双端结果尚待用户验收。
