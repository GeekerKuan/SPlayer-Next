# 分步实施计划

先阅读 [设计](./design.md)，以 SPlayer-Next 为基线，遵循现有中文 JSDoc、shared 类型、shallowRef、有界缓存与清理规范。

## 0. 迁移与证据归档

复制旧仓库的 Git 源码基线，应用已完成的播放同步补丁；不向源码包搬入 node_modules、打包产物、解包安装目录或账号 profile。记录来源 commit、旧补丁和测试差异。调查参考项目与许可，协议资料集中放 `protocols/netease-native/`。设计文档先于实现保存。

## 1. 消息核心

1. 定义 shared SocialApi/实体/能力，建立独立 native eapi transport 与 endpoint 注册表。
2. 对当前本人账号只读试验会话/历史/通知 eapi；记录成功码、schema 和隐式已读行为，不回退 weapi。
3. 实现输入校验、分页/去重、未读水位、发送限流和同 clientId 去重；发送失败不自动重放。
4. 实现账号隔离、加密缓存、单轮询器、隐藏暂停、断线退避和 AbortController 清理。
5. 接入 typed preload、IPC 来源校验和退出清理。不能在渲染进程暴露 Cookie、任意 URL 请求或 CDP evaluate。

## 2. 原生页面

1. 新增 /messages 路由、侧边栏元数据与默认导航（兼容已有侧边栏排序）。
2. 复用 S 组件，建立左会话右聊天，支持四页签共用详情、自动拉取、更多历史、草稿、Enter/Shift+Enter 和中文输入法；不保留额外搜索/UID/页面刷新控件。
3. 两侧使用 SVirtualList；聊天锚点保持、底部跟随/新消息按钮；通知页签和分页。
4. 显示发送中/成功/失败/结果未知。只有已验证的回执和邀请操作才提供可用按钮；本地已读不能显示为对方已读。
5. 页面卸载/停用/隐藏/窗口销毁释放监听、轮询和旧请求。

## 3. 阶段一验收门槛

执行协议测试、服务生命周期/账号隔离测试、渲染测试、typecheck、lint、生产构建。随后双账号验证收发与原生卡片，记录内存样本。私信回发与接受邀请已通过真实双账号验证后进入阶段二；仍只有 fixture 的能力继续标记“待实机”。

## 4. 低成本 WS 调研

提供只连接既有 loopback CDP 的被动观测脚本。监听 Network.webSocketCreated/FrameSent/FrameReceived，默认只保存长度、方向、opcode 和脱敏字段结构；不保存 Cookie、Authorization、原始帧或私信正文。观察打开私信、收到测试消息、一起听加入/控制/断线的事件关联。

进入 WS 实现前必须明确：端点、握手、认证更新、心跳、压缩/序列/ACK、补历史和重连续传。资料不足则继续 eapi 轮询，不自行编造私有帧。不应把 CDP 自己的 websocketDebuggerUrl 当成网易云推送端点。

## 5. 阶段二

独立 PC eapi 为默认，CDP 为用户主动选择的兼容方式。先实现直接状态/队列读取、版本向量和命令序列，再接入接受/创建/心跳/退出/加歌；复用 SPlayer 播放器、歌词、统计、系统媒体控制，房间期间限定网易云官方音源。前台操作等待在途只读刷新，取消旧账号响应，远端指令禁止回发。

双账号联调时必须关闭官方客户端，逐项核实加入、持续心跳、双向控制、歌单和进度同步，再验证独立建房和好友可加入。加入成功不能代替主机建房验收。断线恢复只读重建状态，拒绝重放结果未知的写请求。设置导航按照用户指定位置接入。

头像、封面下沉与时长总结卡片在独立协议稳定后接入，规格见 [后续界面需求](./follow-up-ui.md)。

## 6. 开源交付

维护 README、贡献指南、协议证据矩阵、第三方许可和复用记录；提供可应用补丁与仅源码压缩包。发布前排除凭证/账号数据/捕获原始流量/缓存/node_modules/原生二进制；新工作流不混入旧播放日志协议目录。

## 当前实施结果

迁移、消息页、独立 eapi、原生通知入口、双模式房间与指定设置位置均已实现。独立加入及主机建房/邀请/歌单/控制已有真实双账号证据；确认回声和拖动回弹修复只在前端实施，已在当前双人房间复测。代码检查与运行边界见协议验证记录。WS 认证/ACK/续传、非空通知、成功撤回、原生通知系统按钮及 Rust/SMTC 正式构建仍按证据列为待验收，不混入已通过项目。头像与封面动效、两个独立展示开关及子窗口改造已完成；可选安卓总结私信卡片仍缺载荷证据，见最新交付文档。

跨端历史/续播、官方分享短链、正常一起听小窗、更多资源卡片、消息滚动与气泡大小已完成本轮代码和自动检查；Mac Actions 已准备。在线状态上报缺认证/心跳/离线协议证据，尚未实现；不会用隐私字段或网络连通冒充。最新实施顺序、接口、待验收边界及最终打包条件见 [本轮迭代](./iteration-2026-10-04.md)。

最新队列与推荐的执行顺序：先修复普通队列污染和退出清理，再保持双向加歌，随后取得手机心动模式的开关及恢复请求，按证据接入独立切换和权限处理。候选来源不能冒充自动续歌。临时队列与持久化兼容已接入，详见 [优化规格与计划](./together-queue-design.md)。
