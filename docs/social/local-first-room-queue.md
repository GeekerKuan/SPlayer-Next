# 一起听本地反馈、房间队列与后续协议研究

本篇更新 `message-polish-and-diagnostics.md` 中的交互加歌与播放行为；旧篇描述的是上一轮实现，以下规则优先。

## 当前交付

1. 普通歌曲直接播放：校验网易云音源、容量与当前房间归属后，先发布本地播放意图；未入队的歌曲仅发送一次 ADD，再发送一次 GOTO。无需先从菜单添加。明确失败回收意图，未知写入只读核验，不重发。
2. 歌单播放全部：去重并排除房间已有歌曲，一次批量 ADD，播放所选列表原来的第一首。普通歌曲双击只添加当前一首，不把所在整页误加进房间。非网易云或云盘曲目仍不能作为房间音源。
3. 暂停、继续、切歌与拖动的匹配确认不重新加载同一歌曲、不强制 seek；引擎仅在明确本地拖动、首次加载所需位置或与有效房间状态相差超过三秒时调整。播放 URL 尚未返回时的 ACK 也不重启加载。其他成员的新指令、失败、超时及房间变化仍可纠正本机状态。
4. 本地一起听队列映射房间队列。删除使用曲目 ID，排序使用曲目 ID 与相对位置，避免陈旧下标；清空保留当前歌曲，单独删除正在播放的歌曲提示先切换。普通本地队列备份和退出恢复继续沿用原桥接实现；接受系统通知邀请也先保存原队列。
5. 歌曲来源可固定为播放历史。房主按保存的来源在队尾补一首未入队的网易云歌曲；历史列表无候选时提示，不把其他平台音源发往服务器。个人推荐与房间推荐分开，个人推荐不再被空房间推荐覆盖。仅播放歌单的原开关保留。
6. 一起听邀请在前台也发送系统通知；Windows/macOS 的接受动作直接进入既有接受流程，重复点击只执行一次。本人邀请、过期邀请、账号变化和已读旧记录仍受原保护。Linux 沿用通知正文打开会话的兜底。
7. 消息左右标题真正使用原项目 `glass-panel`，渐变遮罩只位于标题范围；滚动条从标题下开始并避开玻璃层。缩短列表上方留白。邀请卡片收紧为同一横行，图标、标题与接受操作对齐，减少多余来源行和底部空白。

## 请求调整与边界

| 操作     | 调整                                                                                                                                 | 原请求保持                                                                                                        |
| -------- | ------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------- |
| 交互 ADD | 发前读取当前房间版本；按已观察的 Windows 列表规则接受 `code=200` 或 `data.result=true`。已受理后不追加三次阻塞确认，由现有轮询确认。 | 同一个列表报告接口，`playlistParam`、毫秒单位、加密与身份字段不变。该成功规则仅用于列表，不扩展到心跳和播放指令。 |
| 未知 ADD | 最多三次只读确认，额外等待 0/300/900ms；不能把未知写入当作确定成功，也不重放。                                                       | 同一个房间状态和列表读取，原传输超时、429 冷却和取消保留。                                                        |
| 队列编辑 | DELETE 使用删除 ID；REPLACE 使用完整顺序，随机模式保留现有随机顺序。仅递增本账号的版本项。                                           | 复用 ADD 所属的原列表报告接口，未新增协议字段。                                                                   |
| 播放     | 本地先发布意图，再等待已有控制请求；相同曲目与小偏差确认不重启音频。                                                                 | 原 `commandInfo` 的 commandType、playStatus、progress、formerSongId、targetSongId、clientSeq 不变。               |
| 续歌     | 房主按所选来源选未入队歌曲；内部自动补歌仍先确认入队才发送原 NEXT。                                                                  | 原推荐读取和批量列表报告；不猜测双人口味算法。                                                                    |

已受理列表保留最多十五秒的临时投影；读取确认后立即删除，超时恢复服务端真实列表并提示。临时投影只作用于本次增删或顺序，不吞掉其他成员的新加歌曲；确认前不叠加第二份列表写入。停止、账号变化、房间变化会清除全部临时状态。没有新增周期轮询；既有 AbortSignal 回收网络和等待。

这些调整保留了改善体验的客户端时序，同时按已有官方 Windows 加歌样本校正列表接受规则；不能称为已经完全复刻所有官方端协议。

## 自动验证与用户复测

本轮 Node 测试 158 项、Vitest 317 项通过。覆盖慢 ADD 下即时播放、批量去重、DELETE/REPLACE、清空保留当前曲、延迟确认、其他成员加歌合并、未知写入不重放、历史续歌、操作取消、URL 解析期间 ACK、前台通知与直接接受。类型检查与应用构建另行执行。真实双端、安装升级、Windows 听感和 Mac 实机行为仍由用户复测，未声称进行过本轮实机性能测量。

## 后续研究顺序

1. 先检查现有 Windows 日志并复核官方列表的锚点、随机列表和加歌事件时序，按证据修正；不因猜测改接口。
2. 应用宝虚拟机 ADB 已连接，Android 13、网易云 9.6.05、shell 非 root。先识别可用的明文观测层；仅抓 TLS 流量不能证明 eapi 参数。用户已授权调试两台官方客户端，无需再次索取同一授权。
3. 观测双方口味推荐的开启/关闭请求及普通列表备份恢复，确认会员、房主权限和响应后再实现。
4. 识别真正在线上报/续期/离线协议；只有在线可见性字段不足以证明已实现在线上报。确认后接入独立默认开启的开关及停机回收。
5. 补充手机聊天结构化载荷，优先一起听时长总结、图片及表情。PC 只有“不支持展示”文字时保留兜底，不凭截图编造时长。
