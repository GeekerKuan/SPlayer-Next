## 使用

登录网易云账号后打开侧边栏“消息”。会话与聊天双栏支持历史分页、虚拟滚动、草稿、输入法安全的 Enter 发送和本机已读标记。消息发出后显示发送状态，不显示未经验证的对方已读回执；发送结果未知时刷新历史核对，避免重复发送。

设置中“消息设置”位于“快捷键配置”和“网络与服务”之间，管理系统消息通知。默认启用后台 10 秒检查；首次刷新不弹历史消息，Windows 原生通知不显示私信正文。禁用通知、退出账号或退出应用时清理后台资源。

播放设置中“播放过渡”和“听歌打卡”之间的“一起听歌”选择实现方式（Windows 可选 CDP，其他平台始终独立），默认 **SPlayer 独立实现**。此模式不启动、不连接官方客户端。登录网易云后从播放栏右下角三点菜单打开一起听子窗口，连接状态、接受新邀请或创建房间；创建时使用当前网易云歌曲，没有时选择首个推荐候选。在子窗口选择最近会话或输入其他好友 UID，再创建/邀请。独立模式房主支持复制官方 163cn.tv 短链（失败时回退平台 H5）；接管或关闭外部房间需用户确认。入房后底栏也有独立入口，三点菜单变为离开。

可选“官方 Windows 客户端（CDP）”：选择 cloudmusic.exe，用户自行开启本机 loopback 调试端口 9229，两款软件必须为同一账号。当前兼容构建为 `3.1.40.205461 / d4d4312`。这条路径由官方客户端播放与维护 IM/RTC；SPlayer 暂停本地引擎。没有自动模式回退，房间内禁止切换方式。

**一起听仅支持网易云歌曲。** 独立模式复用 SPlayer 原生播放器，只允许房间当前 songId 与网易云官方完整音源，不使用本地/QQ/酷狗/流媒体或插件兜底，也不使用可能来自插件的旧音频缓存。歌曲不可播放时暂停并提示，不自动向对方切歌。软件原有播放、暂停、切歌、进度拖动和系统媒体控制接入房间指令，接收远端指令不回发。

推荐优先使用房间列表返回的 `rcmdSongIds`，没有时读取当前账号每日推荐；服务端推荐的生成规则未确认，不声称是双方共同偏好。用户主动加歌时递增自己的版本，ADD 不覆盖队列，最多 500 首。私人 FM 不自动填充房间。

独立模式主进程每 2 秒读取队列和播放指令，每 20 秒用实际播放状态维持心跳，读取可退避重试，写操作不自动重放。离开消息页继续维持已加入房间；账号退出/房间结束释放音频与资源。应用重启只可恢复本机加密记录中已验证加入的同账号同房间，先核验状态和心跳；不重放接受或邀请。未归属 SPlayer 的房间只读显示；可明确选择“关闭旧房间并新建”，服务端确认退出后才创建，失败不会自动重试。

独立模式的听歌时长、历史、统计、歌词、封面与 SMTC 沿用实际音频的原有链路，不增加第二个统计器。CDP 兼容模式仅累计可见且连接中的观察时段，不推算官方客户端在 SPlayer 关闭页面后的时长，不重复提交打卡。

官方客户端关闭后的独立加入、建房、邀请和主机控制已实测，手机确认暂停、继续、拖动和切歌同步。拖动立即更新本机播放，上传期间继续播放；收到匹配确认且本地进度相差不超过 3 秒时不重复跳转。差值较大、失败或新远端操作会校准，写操作不重放。其余验收项和限制请查协议验证记录；这不是完整 Windows 私有协议复刻。

跨端续播在播放设置默认开启，播放历史合并服务端其他设备的记录并去重；续播仅在服务端提供可用入口且用户点击时执行。不会把远端历史计入本机统计，关闭开关会取消请求并清空远端快照。在线上报协议未确认，暂未加入无效开关。

## 网络和资源边界

本模块独立位于 `electron/main/services/social/netease-native/`，固定 PC eapi 域名，不通过原音乐 API 的 weapi 路径；只共享主进程登录态和代理桥。Cookie 不进入渲染层，IPC 不接收调试表达式、任意 action 或 URL。

发送保护为每账号 1 秒间隔、每分钟 20 次；这是本应用策略。会话 500、20 个历史会话各 500 条、通知 200、缓存 2 MiB；safeStorage 加密不可用时不明文落盘。只读请求可重试，消息/房间操作不重放结果未知的请求。页面和后台服务各自拥有生命周期，页面订阅和 CDP 在卸载时释放，独立房间心跳由应用拥有，退出房间或账号后清理。

## 开发

```bash
pnpm install
pnpm typecheck
pnpm test
pnpm lint
# 已有兼容的 native 模块时
pnpm exec electron-vite build
```

新增功能没有新增 npm 依赖。本工具环境没有 Git Bash，验证使用提供的 PowerShell；源码遵循 AGENTS.md。本地未重建 Rust；本地编译复用与当前源码提交一致的官方 nightly.922 原生模块，摘要见 native-provenance.json。源码交付不含二进制，开发者仍走项目原有 Rust 构建流程。

## 被动 WS 观测

```bash
pnpm exec tsx scripts/social/inspect-client.ts 9229 "C:/Apps/CloudMusic/cloudmusic.exe"
pnpm exec tsx scripts/social/capture-ws.ts 9229 ../work/ws-metadata.json "C:/Apps/CloudMusic/cloudmusic.exe"
```

只连接已启用的官方客户端，脚本不自动重启。最多观测 60 秒、500 事件、50 连接，仅记录 origin、方向、opcode、长度和字段类型。原始帧、headers、Cookie、query 和私信正文不进入交付。已观察到应用 `wss://im.music.163.com`；握手、认证、ACK 和恢复尚未完整验证，生产消息仍采用 eapi 轮询。

构建、测试、内存与双端验收按证据分开记录，见验证文档。
